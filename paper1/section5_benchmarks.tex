\section{Empirical Validation}
\label{sec:benchmarks}

The Constitutional Enclosure Theorem guarantees that an external Safe Rust
caller cannot construct a BTV \texttt{Verdict} through the public API without
the required tokens.  Does that guarantee impose a runtime cost?  We answer
across payload sizes, thread counts, and two persistence postures, in the
direction the measurements point---which is not the flattering one.

% ----------------------------------------------------------------
\subsection{Experimental Setup}
\label{sec:setup}

\paragraph{Methodology.}
Micro-benchmarks use Criterion's \texttt{iter\_batched} discipline with
\texttt{black\_box} on every input crossing an optimization boundary and a
per-iteration seed making each hashed context distinct.  The sweep
harness's hot path carries no injected synchronization; percentiles are
estimated online with the $P^2$ algorithm~\cite{jain1985p2} and are
therefore \emph{estimates}, not order statistics.  Each configuration runs
five trials; we report medians and the trial-to-trial coefficient of
variation (CV).  Iteration counts are calibrated per (payload, mode) using
that mode's own operation, so they are not comparable across modes.

\paragraph{Hardware, software, and what this collection is not.}
All three tables come from one collection on one host: an Intel Xeon
virtual machine, 4~vCPUs, Linux x86\_64, \texttt{rustc}~1.98.1 pinned via
\texttt{rust-toolchain.toml}, 5\,s wall target per configuration.  Two
constraints bound it.  The durable arm writes to a containerized overlay
filesystem, so its \texttt{fsync} cost is a \emph{lower} bound on
bare-metal storage; and this is a reduced-footprint snapshot---the
90\,s-per-configuration run on dedicated hardware, and a second-platform
collection with the current code, remain open obligations in the
artifact's evidence manifest.  We publish it with its environment
fingerprint because it is reproducible today and internally consistent,
not as a headline result.  \texttt{aarch64} coverage is compile-and-test
only and carries no performance claim.

\subsection{Results}
\label{sec:results}

\paragraph{Construction latency.}
Table~\ref{tab:construction} reports the end-to-end cost of
\texttt{Verdict::new}---BLAKE3 context hashing, authority-signature
verification, HMAC-SHA256 sealing, and allocation.  The payload-scaling
portion of the curve is BLAKE3; the $\approx$5.36\,\textmu{}s floor is
dominated by two HMAC-SHA256 computations---verifying the compliance
token's authority signature, then sealing the verdict---plus hex encoding
of the evidence identifier.  Each is work an accountable system must
perform whatever its governance architecture; none is attributable to the
type discipline, which emits no instruction at all.

\paragraph{Thread scaling, and where contention actually lives.}
Table~\ref{tab:platforms} separates the two persistence postures under
concurrency.  The in-memory path is flat---7.82\,\textmu{}s at one thread
and at four, CV below 0.3\%---the empirical signature of the absent lock
contention claimed in Section~\ref{sec:type_system}: the linear discipline
introduces no shared state to contend for.  The durable path inverts that.
Its median degrades mildly (261 to 292\,\textmu{}s) while its p99 rises
from 512\,\textmu{}s to 28\,ms as four threads serialize on one log
connection.  That tail belongs to the chosen sink, not the type system,
and it is the honest answer to whether this design ships production-ready:
the reference \texttt{LogSink} is a single-writer SQLite file, and scale
needs a sink built for concurrent append.  The type-level guarantee is
indifferent to that choice; the latency budget is not.

\paragraph{Why the construction rows differ.}
Table~\ref{tab:construction} times the full public path, including token
issuance and verification.  Table~\ref{tab:fivemode}'s smaller
``prebuilt-token binding'' row creates tokens outside the timed region and
measures only their binding.  It is not a second end-to-end estimate.

\paragraph{What accountability costs against the status quo.}
Table~\ref{tab:fivemode} is the comparison an architect actually faces.
Against a status quo that logs the complete decision context, the durable
BTV pipeline is $11.1\times$ \emph{slower} at 4~KiB; against one that logs
only a digest and metadata, $155.5\times$ \emph{slower}.  We report both
because which one counts as ``the status quo'' is a modelling choice
rather than a fact about BTV, and we state the direction plainly: an
earlier revision of this section claimed $2.6\times$ \emph{faster} against
the full-context baseline, a figure produced by a benchmark defect
described below.

The multiplier is real, and so is what the baseline buys with it.  The
fire-and-forget arm is fast partly because it is permitted to lose the
record: the artifact's contrast experiment
(\texttt{tests/test\_status\_quo\_contrast.rs}) shows a dead logger and a
backlogged logger each returning success for a thousand decisions while
every record is discarded---no error surfaced, no trace left.  That is the
silent decision of Section~\ref{sec:intro}, reproduced under laboratory
conditions.  BTV's durable arm cannot reach that state: it returns a
\texttt{Verdict} only after the row exists.  The comparison is therefore
not like-for-like, and we decline to present it as though it were.  What
the numbers price is not one logging strategy against another, but the
difference between a record that exists and one that might.

\paragraph{Correction of record.}
These figures replace earlier ones that were wrong: the harness seeded
each payload from a trial-local counter, so later trials replayed evidence
the log already held, and the append-only sink correctly returned success
without a second write.  Four of every five trials measured that no-op.
Every durable payload now draws from one process-wide atomic counter, and
each run asserts that rows persisted equals operations issued---this
collection passed exactly, 1{,}803{,}460 of 1{,}803{,}460.  We record the
correction in the manuscript, not only the artifact, because a defect that
makes the accountable path look cheaper than it is defeats this work's
purpose as thoroughly as the failure mode it was built to prevent.

\subsection{Worked Examples}
\label{sec:worked-examples}

Three worked examples demonstrate BTV in semi-realistic scenarios: credit
scoring under LGPD (30-day appeal window), hiring screening under EU AI Act
Art.~86 (high-risk classification), and emergency triage (where \texttt{Allow}
decisions also require evidence).  Each example constructs verdicts from
domain-specific payloads and verifies integrity.  Source code is included in
the companion repository (\texttt{examples/}).
