\section{Discussion}
\label{sec:discussion}

The Constitutional Enclosure Theorem establishes a strong structural
guarantee within a precisely bounded scope. This section examines
those boundaries honestly, identifies limitations of the reference
implementation, and proposes extensions that close each gap without
weakening the core invariant.

% ----------------------------------------------------------------
\subsection{Scope and Boundaries of the Guarantee}
\label{sec:scope}

\paragraph{Unsafe Rust.}
The scope limits of \S\ref{sec:encapsulation} and \S\ref{sec:threat}
apply here too: enforcing a zero-\texttt{unsafe} policy across the
dependency graph (auditable via \texttt{cargo geiger}~\cite{cargogeiger})
is an operational decision, not a theoretical barrier, and requires no
change to the BTV crate itself.

\paragraph{Semantic truthfulness and the AttestableContext extension.}
The theorem guarantees that \emph{some} byte sequence was hashed and
bound to a verdict, not that it faithfully represents the context
presented at inference time: a caller could pass
\texttt{b"placeholder"} to \texttt{EvidenceToken::new} and obtain a
structurally valid token. A sealed \texttt{AttestableContext} trait
would narrow this gap without weakening the core invariant:

\begin{lstlisting}[language=Rust,caption={AttestableContext trait
  (proposed extension)}]
pub trait AttestableContext: Sealed {
    fn canonical_bytes(&self) -> &[u8];
    fn schema_version(&self)  -> u16;
    fn source_attestation(&self) -> SourceAttestation;
}
\end{lstlisting}

\noindent
where \texttt{SourceAttestation} carries a signature over the payload
from an HSM/TPM-backed key; \texttt{EvidenceToken::new} would accept
\texttt{impl AttestableContext} instead of \texttt{\&[u8]}, reducing
forgery to compromising that key rather than passing an arbitrary
byte string. This tightens the type law to
$V \multimap (E_{\text{attested}} \otimes C)$ --- strictly stronger
than $V \multimap (E \otimes C)$, since every proof of the original
invariant is also a proof of the attested variant --- while the
\texttt{Sealed} supertrait keeps external crates from implementing
\texttt{AttestableContext}, preserving Axiom~3's closed perimeter.

\subsection{Limitations of the Reference Implementation}
\label{sec:limitations}

The \texttt{silent-decisions-proof} kernel is a proof-of-concept
designed to validate the theoretical claims of this paper.
Four implementation choices trade production robustness for
clarity of exposition; each has a well-defined remediation path.

\paragraph{L1 — Static HMAC key (mitigated).}
The reference implementation reads the HMAC key from
\texttt{BTV\_HMAC\_KEY} at runtime, falling back to a compile-time
constant only when unset, closing L1 for deployments that inject a
key from an HSM/KMS. This surfaces a recurring asymmetry: the
verdict seal's strongest guarantee holds only when
\texttt{BTV\_HMAC\_KEY} shares HSM/KMS infrastructure with the audit
log's own signing key, since overall non-repudiation is bounded by
the weaker of the two. The type-level guarantee
(Theorem~\ref{thm:enclosure}) is independent of key management and
holds regardless of the key source.

\paragraph{L2 — \texttt{ComplianceAuthority} factory, HMAC-signed
(implemented).}
The \texttt{ComplianceToken::new} constructor was originally
\texttt{pub}, letting any external crate self-declare a jurisdiction
without validation \emph{or} authority. The reference implementation
restricts it to \texttt{pub(crate)} behind a \texttt{ComplianceAuthority}
factory that (a) validates the jurisdiction against an allowlist of
recognised regimes (\texttt{BR-LGPD}, \texttt{EU-GDPR},
\texttt{EU-AI-ACT}) and (b) signs \texttt{(jurisdiction, policy\_version,
deadline\_hours)} with an HMAC key read from
\texttt{BTV\_AUTHORITY\_KEY}. \texttt{Verdict::new} independently
verifies that signature against the same recognized key before
constructing a \texttt{Verdict}, rejecting a forged token or one
issued by a differently-keyed authority (\texttt{BtvError::InvalidTokenSignature}) ---
allowlist membership alone is no longer sufficient, closing the gap
between "validated" and "authorized." The type law tightens to
$V \multimap (E \otimes C_{\text{signed}})$; the encapsulation
boundary (Axioms~1--3) is preserved.

\paragraph{L3 — Single-node evidence chain.}
\texttt{EvidenceToken} captures a single BLAKE3 hash; multi-step
pipelines (retrieval, re-ranking, generation, scoring) each carry
accountability implications. A \emph{chain} of evidence tokens, each
stage consuming the prior and producing a new one, generalises
naturally while preserving $V \multimap (E \otimes C)$ at each step.

\paragraph{L4 — Polyglot pipelines.}
Production AI systems rarely run in a single language: Python
orchestrators, C++ inference engines, and Java gateways must all
participate in the same governance boundary. Since the theorem holds
within Safe Rust (Axiom~\ref{ax:encap}), external code is
$\Gamma_{\text{ext}}$ by definition and cannot construct a
\texttt{Verdict} directly; \S\ref{sec:ffiboundary} analyses this as a
threat model, where the PyO3 gateway keeps external callers inside
$\Gamma_{\text{ext}}$ and a \emph{BTV sidecar} per service could chain
a fresh \texttt{EvidenceToken} at each stage, addressing L3 and L4
jointly.

% ----------------------------------------------------------------
\subsection{CAL Design Trade-Offs}
\label{sec:cal}

A production governance kernel faces a three-way tension among
\textbf{C}onsistency (every verdict carries a causally-bound evidence
chain), \textbf{A}vailability (the system always issues a verdict in
finite time), and \textbf{L}egality (tokens come only from a verified
authority). Existing audit-logging designs choose
consistency-with-availability over legality: decisions keep issuing
even when the logging pipeline fails, so the log carries no
enforceable evidentiary guarantee. BTV chooses the opposite: it fails
securely rather than issuing unevidenced verdicts, accepting reduced
availability, partially recovered by \texttt{EscalatedVerdict}
(\S\ref{sec:escalated}). This is a practical design observation, not a
formal impossibility result; whether an FLP-style
theorem~\cite{flp1985} holds for accountability systems is open.

% ----------------------------------------------------------------
\subsection{Future Work}
\label{sec:future}

Six directions are most immediate: (1)~implementing
\texttt{AttestableContext} (\S\ref{sec:scope}) to close the
semantic-truthfulness gap; (2)~extending the evidence chain to
multi-step pipelines via the sidecar pattern (L3, L4) for
retrieval-augmented and agentic architectures; (3)~mechanising the
Constitutional Enclosure Theorem in a proof assistant (Lean~4 or Coq),
elevating it from a machine-checked Rust proof to a fully mechanised
one; (4)~testing whether a formal CAL impossibility result holds under
asynchrony (\S\ref{sec:cal}); (5)~unifying \texttt{Verdict} and
\texttt{EscalatedVerdict} under \texttt{AccountableDecision} into the
composed invariant $(V_{\mathrm{auto}} \oplus V_{\mathrm{esc}})
\multimap R$; and (6)~composing BTV's construction-time guarantee with
tamper-evident persistence and privacy-preserving redaction, which we
conjecture is tractable because the three operate at distinct layers
with non-overlapping trust assumptions.
